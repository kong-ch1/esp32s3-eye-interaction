# 第1周 · 真实现测记录

**设备**：ESP32-S3-EYE（板载 **QMA6100P** 三轴加速度计，I2C 地址 0x12，SDA=GPIO4 / SCL=GPIO5。原理图标注的 QMA7981 已停产换代，实装经 CHIP_ID=0x90 及特有寄存器探测确认为 QMA6100P，见 README「型号勘误」）
**设备标识**：`device_id = team01-esp32s3eye`
**链路**：板子 WiFi（IP `10.1.41.160`）→ HTTP POST 1Hz → 本机服务器 `10.1.41.18:8000` → SQLite → 网页展示

## 二、时间核对说明

- 板子无 RTC，`device_ms` 是上电毫秒数，只能用于测间隔
- 权威时间为服务端 `server_ms`（收到时刻），页面显示的也是服务器时间
- 上报间隔核对：seq 每秒 +1，与固件 1000ms 定时一致

## 三、"未更新"验证（当堂验收点）

1. 正常态：页面右上角「实时更新中」，`/api/latest` 返回 `stale: false`、`age_seconds < 2`
2. 板子断电后：页面数值冻结、保留最后的服务器时间
3. 5 秒后：页面提示「未更新 · 已 N 秒」，`/api/latest` 返回 `stale: true`
4. 重新上电：页面自动恢复刷新

## 四、关于角速度的说明

板载 IMU 为 **QMA6100P，仅有三轴加速度计、无陀螺仪**（经寄存器级排查确认：整片 0x00~0x3F 寄存器空间中只有三组加速度数据在动，无角速度通道；见 `debug_logs/` 的 dump 数据），故 gx/gy/gz 固定为 0。本组呈现的设备数据为**三轴加速度**。如后续任务需要角速度，计划外接 MPU6050（六轴）挂同一 I2C 总线。

## 五、数据来源证据（页面未写死数值）

- 每条记录带 `src_ip = 10.1.41.160`（板子 WiFi 地址，与本机 10.1.41.18 不同网段设备）
- `device_id = team01-esp32s3eye` 为本组独立标识
