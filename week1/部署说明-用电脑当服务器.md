# 部署说明 · 用电脑代替 VPS

课程要求把服务部署出去（"没有 VPS 可以直接使用自己的电脑当作服务器"）。
本文记录**用这台电脑充当服务器**的实际部署形态、实测结果，以及**与真正 VPS 的差距**。

---

## 一、当前部署形态（已跑通）

```
┌───────────────────────┐          ┌─────────────────────────────┐          ┌──────────────────┐
│  ESP32-S3-EYE 板子     │  WiFi    │  服务器（这台电脑）          │  HTTP    │  浏览器           │
│  10.1.41.160          │ ───────► │  10.1.41.18 : 8000          │ ◄──────► │  局域网内任意设备  │
│  每 1 秒 POST 一条     │  POST    │  监听 0.0.0.0（不是仅本机）  │          │  http://10.1.41.18:8000 │
│                       │          │  SQLite 落库 + 视频中继      │          │                  │
│  MJPEG 流 :81  ◄──────┼──────────┤  服务器作为唯一上游拉流       │          │                  │
└───────────────────────┘  拉 1 路  └─────────────────────────────┘          └──────────────────┘
```

| 角色 | 地址 | 说明 |
|---|---|---|
| 服务器 | `10.1.41.18:8000` | 监听 `0.0.0.0`，**不是只监听 127.0.0.1**，所以局域网内其他设备能访问 |
| 板子 | `10.1.41.160` | 固件里 `SERVER_URL` 写死指向 `http://10.1.41.18:8000/api/data` |
| 网页 | `http://10.1.41.18:8000` | 手机、别的电脑连同一个 WiFi 就能打开 |
| 摄像头 | 服务器 `/api/camera` | 服务器从板子 `:81` 拉一路流再分发给所有浏览器 |

**关键点：这不是"本机跑跑看"。** 板子是一台独立设备，通过网络访问另一台机器上的服务；
网页也是通过网络访问——这条链路跨了三台不同的主机（板子 / 电脑 / 浏览器所在设备）。

## 三、与真正 VPS 的差距（诚实说明）

| | 现在（电脑当服务器） | 真 VPS 需要补什么 |
|---|---|---|
| **可达范围** | 仅同一个局域网 | 需要有公网 IP 的机器；或在路由器上做端口映射；或用内网穿透（frp / cloudflared / ngrok） |
| **服务器地址** | 固件里 `SERVER_URL` **写死** `10.1.41.18` | 改成公网地址 → 现在需要**重新编译+烧录**（见下方改进建议） |
| **摄像头** | 服务器**主动拉**板子的流（两者同网段，能直连） | VPS 在公网、板子在 NAT 后面，**拉不到** → 必须改成**板子主动推流**给服务器 |
| **稳定性** | 电脑关机/休眠就断 | VPS 常驻；另建议加 systemd/supervisor 守护 |
| **安全** | 无鉴权（同网段可下发指令） | 至少要加 token 鉴权 + HTTPS，否则等于公网开放控制接口 |

**所以现在的部署满足课程"用电脑代替 VPS"的要求，但"外出远程访问"还没有解决** ——
那需要上面「可达范围」那一行的某一种做法。

## 四、要搬到真 VPS，按这个顺序改

1. **服务端**：`server.py` 直接拷到 VPS 上跑即可（零第三方依赖，只要 Python 3）。
   注意 `--host 0.0.0.0`，并在安全组/防火墙放行端口。
2. **固件**：把 `main.c` 里的 `SERVER_URL` 改成 VPS 地址，重新编译烧录。
   → **建议先做这一步的改良**：把 `SERVER_URL` 从编译期常量改成可在运行时配置
   （存 NVS，配一个简单的串口命令或配网页面），这样以后换地址不用重新烧固件。
3. **摄像头**：把角色反过来 —— 板子主动把 MJPEG 推给服务器（板子写 HTTP POST /
   chunked 到服务器的接收端点），服务器再分发给浏览器。现在的"服务器拉流"在 NAT 后不可用。
4. **鉴权**：给 `/api/command` 加 token；网页侧带 token；建议套一层 HTTPS。

## 五、怎么复现这套部署

```bash
# 1) 启动服务器（会打印本机与局域网两个地址）
python week1/server/server.py
# 或双击 week1\start_server.bat（独立窗口，不受会话影响）

# 启动输出示例：
#   [week1] 服务已启动
#   [week1]   本机访问  : http://127.0.0.1:8000
#   [week1]   局域网访问: http://10.1.41.18:8000   ← 板子靠这个地址上报

# 2) 板子上电即可（固件已烧录，自动连 WiFi 并上报）

# 3) 同 WiFi 下用手机/另一台电脑打开
#    http://10.1.41.18:8000

# 4) 真机验收（命令行证据链）
python week1/tools/cmd_acceptance.py --samples 12 --interval-ms 100 --save

# 5) 真实浏览器实测（自动点击按钮并截图）
python week1/tools/browser_test.py
```
