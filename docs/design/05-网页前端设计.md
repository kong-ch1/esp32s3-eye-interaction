# 05 · 网页前端设计

实现文件：[`week1/web/index.html`](../../week1/web/index.html) —— **单文件、无构建步骤、无 CDN、无框架**，纯原生 HTML/CSS/JS。

## 1. 为什么不用框架

课程环境的网络不可靠（实测连 GitHub 都会 502），机器上的网络也不一定允许访问 CDN。
**无 CDN 依赖**意味着把文件拷到任何地方双击就能打开，不会因为拉不到 `vue.min.js` 而白屏。

趋势曲线用原生 `<canvas>` 手绘，不引入图表库。

## 3. 关键配置常量

```javascript
// API 基址：优先用当前页面的 origin
// 如果页面被当成静态文件直接打开（file:// 或别的静态预览端口），
// 就退回到 127.0.0.1:8000
const API_BASE = (location.protocol === 'http:' || location.protocol === 'https:')
  ? location.origin
  : 'http://127.0.0.1:8000';

// 摄像头模式：'server' = 走服务器中继（默认）；'direct' = 直连板子（仅排障用）
const CAM_MODE = 'server';
const CAM_BASE = 'http://10.1.41.160:81';
const CAM_STREAM    = CAM_MODE === 'server' ? API_BASE + '/api/camera'        : CAM_BASE + '/stream';
const CAM_HEARTBEAT = CAM_MODE === 'server' ? API_BASE + '/api/camera/status' : CAM_BASE + '/ping';
```

> 修过的 bug：原来用相对路径 `/api/*`，当页面被 IDE 以静态预览方式打开（端口 60243）时，请求会打到静态服务器上而不是 8000 端口，表现为「无法连接服务」。固定 `API_BASE` 后解决。

## 4. 数据轮询与「未更新」提示

```
每 1 秒：GET /api/latest
   │
   ├─ 拿到记录 → 更新卡片数值、合加速度、温度、内存、RSSI、表格
   ├─ age_seconds > STALE → 状态胶囊变红，显示「未更新 · 已 N 秒」
   └─ 数值冻结在最后一次的值，时间保留最后的 server_ms
```

设计上**页面不自己倒计时**，每轮都用服务器返回的 `age_seconds` —— 这样显示的时间永远与服务端一致，且能同时反映「板子停了」和「服务器停了」。

## 5. 性能优化（第二轮重写时加入）

| 问题 | 做法 |
|---|---|
| 每秒重设 `canvas.width` 会重新分配画布，卡顿 | 改用**数据签名**（id 首尾）+ 尺寸双重判定，未变化则**跳过重绘** |
| 请求可能挂住 | 加 6 秒超时 `AbortController` |
| 后台标签页空转 | 标签页不可见时**暂停轮询**，切回立即补一次 |
| 静默失败 | `fetch` 检查 `r.ok`，失败不当作成功 |
| 重连时浏览器缓存住失败状态 | 重连 URL 必须带 `?nocache=Date.now()` |

## 6. 卡片与表格

- 主区 **3 列 6 张卡片**：加速度 X / Y / Z、合加速度 |a|、芯片温度、剩余堆内存；再单独一张 WiFi 信号卡片（共 4 列布局）。
- 堆内存卡片带 `.sub` 副行「已用 X MB / 共 Y MB」，`title` 悬浮显示**历史最低水位**（持续下降 = 疑似内存泄漏）。
- 表格列：id / 时间 / 序号 / ax / ay / az / |a| / 温度 / 剩余MB / 已用MB / 来源IP（`colspan` 随列数变动维护）。
- 缺数据时显示「—」而不是 0：

```javascript
const fmt = (v, n = 3) => (v === null || v === undefined) ? '—' : Number(v).toFixed(n);
const mb  = (b) => (b === null || b === undefined) ? '—' : (Number(b) / 1048576).toFixed(2);
const num = (v) => (v === null || v === undefined) ? null : Number(v);
```

老固件不上报 `total_heap` 时，「已用 / 共」显示「—」，不硬算成 0。

## 7. 角速度的移除

**QMA6100P 只有三轴加速度计，没有陀螺仪**，`gx/gy/gz` 恒为 0。第二轮重写时做了以下清理：

- 删掉 3 个角速度卡片
- 删掉曲线切换按钮（加速度/角速度）与 `gyr` 序列
- 删掉表格里的 `gx/gy/gz` 列
- 清理掉全部 `data-page-node-id` 噪音属性
- 新增「合加速度 |a|」卡片与表格列

固件与数据库仍保留 `gx/gy/gz` 字段（恒 0，无害），彻底清需改固件重烧 + 改表。

> 顺带确证：QMA6100P 官方 datasheet 明确为 *three-axis accelerometer*。网上若干页面称其为「6 轴 IMU 带陀螺仪」是 AI 生成的错误信息（连封装都误写成 LGA-14，官方是 LGA-12），不可信。

## 8. CSV 下载

```javascript
// 直接让浏览器下载，不用 fetch + Blob —— 几万条不占内存
window.location.href = API_BASE + '/api/export.csv';
```

范围下拉 `#csvRange` 提供：最近 100 / 1000 条、最近 1 / 6 / 24 小时、最近 3 / 7 天、全部记录。选「全部」时不传参，走服务端默认上限。

表格标题右侧显示「累计 N 条（上限 M）」，启动时通过 `/api/devices` 汇总。

## 9. 摄像头区块

见 [`06-摄像头链路与视频中继.md`](06-摄像头链路与视频中继.md)。要点：

- `<img src>` 直接指向 MJPEG 流地址，靠浏览器原生 multipart 解码
- **每 3 秒 `/ping` 心跳**：两次失败 → 判死自动重建；`clients=0` 但自己以为还在看 → 判定画面已冻结，同样重建
- 失败退避重试（2s 递增到 10s，20 次后提示重新上电）
- 心跳解析兼容 server / direct 两种模式（server 读 JSON 的 `state` / `last_frame_age`，direct 读板端 `clients=N`）
