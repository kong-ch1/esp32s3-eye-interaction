# 02 · 硬件平台与传感器

## 1. 开发板概况

**ESP32-S3-EYE**（乐鑫官方 AI 视觉开发板）

| 项目 | 规格 |
|---|---|
| SoC | ESP32-S3-WROOM-1（ESP32-S3R8），双核 Xtensa LX7 @240MHz |
| 无线 | WiFi 4 (2.4GHz) + BT 5 LE，带 AI 向量指令 |
| 内存 | **8MB Octal PSRAM** + 512KB 内部 SRAM |
| Flash | **8MB**（`esptool flash_id` 实测；boot 日志显示的 2MB 是 sdkconfig 里的设置值，不是物理容量） |
| 摄像头 | **OV2640** 200 万像素，66.5° FOV，DVP 并口，**自带 JPEG 硬编码** |
| 加速度计 | **QMA6100P** 三轴（原理图标注 QMA7981，见第 3 节勘误） |
| 麦克风 | 数字 I2S MEMS，61dB SNR |
| 存储 | MicroSD 卡槽 |
| 按键 | 6 个（含 BOOT / RST） |
| 显示 | 子板 1.3" LCD 240×240（ST7789，SPI） |
| 下载口 | Micro-USB（**非 Type-C**），经 GPIO19/20 走内置 USB-JTAG/Serial，无需 CP210x 芯片 |

板子分为两块：**MB 主板**（摄像头/SD/麦克风/按键/电池焊点+充电 IC）与 **SUB 子板**（LCD），通过排针连接。

> 注意：20pin 排针只引出 3V3 / GND / IO48 / IO47 / IO44 / IO21 / IO43 / IO0 / IO3 / IO45 / IO46。
> 其中**干净空闲的只有 IO21** —— 板载 GPIO4/5 的 I²C 并未引出，所以想外挂传感器（如陀螺仪）只能走软件 I²C 到 IO21。

## 2. 引脚定义（实测可用）

### 2.1 加速度计 I²C

| 信号 | GPIO |
|---|---|
| SDA | GPIO4 |
| SCL | GPIO5 |
| 端口 | `I2C_NUM_0`，400 kHz |
| 从机地址 | `0x12` |

### 2.2 摄像头 OV2640（取自 esp-bsp 官方 `bsp/esp32_s3_eye` 定义）

| 信号 | GPIO |
|---|---|
| XCLK | 15 |
| PCLK | 13 |
| VSYNC | 6 |
| HREF | 7 |
| D0–D7 | 11, 9, 8, 10, 12, 18, 17, 16 |
| SCCB SDA/SCL | **复用 GPIO4/5**（与加速度计同一条总线） |

**关键约束**：摄像头 SCCB 必须复用 IMU 那条 I²C 总线，配置为 `.pin_sccb_sda = -1` + `.sccb_i2c_port = I2C_NUM_0`。若填具体引脚号，esp32-camera 会自己再装一套旧版 I²C 驱动抢 GPIO4/5，结果就是**摄像头起来了、IMU 反而读不到数据**。两个设备同挂一条总线（IMU=`0x12`，OV2640=`0x30`）互不影响。

## 3. 型号勘误：原理图写 QMA7981，实装是 QMA6100P

这是本项目**所有寄存器级异常的根源**，也是最有价值的一条独立发现。

### 3.1 判据对照

| 判据 | 本板实测 | QMA6100P | QMA7981（公开手册） |
|---|---|---|---|
| CHIP_ID (0x00) | **0x90** | 0x90 ✓ | 0xE7 ✗ |
| 0x45 CHIP_STATE / 0x46 ULPS | ACK（0xC0 / 0x1A） | 有此寄存器 ✓ | 无 ✗ |
| 0x33 NVM / 0x4A / 0x56 / 0x5F | 全部 ACK | 有 ✓ | 无 ✗ |
| ±2g 量程码 | `0b0001` 生效，`0x00` 非法 | `0b0001` ✓ | 对不上 ✗ |
| 量程档位 | ±2/4/8/16/32g 全接受 | 位编码 `0x01/0x02/0x04/0x08/0x0F` ✓ | 老手册无 ±32g ✗ |
| 软复位寄存器 | 0x36 写 0xB6 有效 | 0x36 = SW_RESET ✓ | 无 ✗ |

### 3.2 原因

QMA7981 已 **EOL 停产**，QMA6100P 是其 **pin-to-pin 兼容的换代型号**（同封装 LGA-12、同 I²C 地址 `0x12`、同 14 位 ADC）。乐鑫后续批次换料后原理图文案未同步，但 esp-bsp 组件库已经改为 `qma6100p`。

### 3.3 复现方法（换任何一块板都能自证）

固件上电自动运行 `imu_identify()`，串口打印：

1. `CHIP_ID(0x00)`
2. 6 个 QMA6100P 特有寄存器（0x33 / 0x45 / 0x46 / 0x4A / 0x56 / 0x5F）的探测结果
3. 5 档量程接受性测试（±2/4/8/16/32g）
4. 结束后自动恢复 ±2g

**实测输出**：

```
CHIP_ID(0x00) = 0x90                    -> QMA6100P
0x33 NVM        = 0x0d
0x45 CHIP_STATE = 0xc0
0x46 ULPS       = 0x1a
0x4a TST0_ANA   = 0x00
0x56 AFE_ANA    = 0x00
0x5f TST1_ANA   = 0x00
量程: 0x01(±2g) OK / 0x02(±4g) OK / 0x04(±8g) OK / 0x08(±16g) OK / 0x0f(±32g) OK / 0x00 非法
```

### 3.4 该发现解释的历史异常

| 曾经的异常现象 | 按 QMA7981 手册的理解 | 真相 |
|---|---|---|
| 写量程 `0x00` 不生效、模长 1.5g | 手册说 `0x00` 是合法值 | QMA6100P 的 `0x00` 非法，`±2g` 应为 `0x01` |
| 三轴数据对不上 | 手册的 14 位补码格式 | QMA6100P 的 LSB[7:2] 才是数据位 |
| Y 轴上电冻结在 -FS | 手册无此现象 | 0x36 是 QMA6100P 的 SW_RESET，写 0xB6 才解决 |

**没有一个是玄学。**

## 4. 传感器特性与标定

### 4.1 输出与换算

- 量程：±2g（寄存器 `0x0F = 0x01`）
- 输出：**14 位左对齐**，需先组装 16 位再算术右移 2 位
- 灵敏度：**4096 LSB/g**（±2g 满量程 16384 计数跨 4g）
- 数据格式：`v = (msb << 6) | (lsb & 0x3F)`，符号位 bit13；LSB bit7 是 NEWDATA 标志

### 4.2 零偏标定（旋转实验：面朝上/朝下静止两点法）

本板零偏偏大，未标定时静止模长在 0.78~1.6g 之间漂移。实测并固化在固件里的标定值：

| 参数 | 值 |
|---|---|
| X 零偏 `CAL_X_OFF` | 2265 计数（= 0.553g × 4096） |
| Y 零偏 `CAL_Y_OFF` | 608 计数（= 0.148g × 4096） |
| Z 零偏 `CAL_Z_OFF` | 1594 计数（= 0.389g × 4096） |
| Z 灵敏度系数 `CAL_Z_SCALE` | 0.912 |

标定后各静置姿态模长 0.97~1.01 g。**换板子需重新标定。**

### 4.3 静态噪声基线（2026-09-14 实测，600 条 / 13.5 分钟，板子静止）

分析工具：[`week1/tools/analyze_noise.py`](../../week1/tools/analyze_noise.py)

| 指标 | 实测值 |
|---|---|
| ax 标准差 | 15.2 mg |
| ay 标准差 | 7.2 mg |
| az 标准差 | 6.3 mg |
| **\|a\| 标准差** | **6.3 mg** |
| 峰峰值 | 约 60 mg（0.06g） |
| **\|a\| 均值** | **1.0030 g** |
| 芯片温度均值 | 52.7 °C |
| 温度 13 分钟内波动 | 13 °C（44.3~57.3） |
| **温度与加速度相关系数** | **≈ 0.02（-0.02 ~ +0.05）** |

**判读**：

- `|a|` 长期均值 ≈ 1.0 g → 传感器与 `CAL_*` 标定均正常，**没坏**。这是判断加速度计是否正常的首要指标。
- 抖动 6~15 mg 属**正常物理噪声**，来源是 MEMS 本底噪声 + 环境微振动 + 供电纹波，**不是**温度漂移（相关系数 ≈ 0 已排除温漂为主因）。
- 芯片温度读数（TSENS）本身噪声不小，不能当精密温度计用。

**结论（答疑用）**：静止 ≠ 读数恒定。网页上保留 3 位小数看到数值跳动是正常物理现象，不是 bug。若希望显示「稳」，可以降低显示位数或加滑动平均，代价是响应变慢。

### 4.4 没有陀螺仪

QMA6100P 官方 datasheet 明确为 **three-axis accelerometer**（纯三轴加速度计）。网上若干页面称其为「6 轴 IMU 带陀螺仪」是 AI 生成的错误信息（连封装都误写成 LGA-14，官方是 LGA-12），不可信。

寄存器级证据：整片 `0x00~0x3F` 寄存器空间中只有三组加速度数据在动，没有角速度通道。因此固件中 `gx/gy/gz` 固定发 0，网页最终也移除了角速度显示。

若后续任务需要角速度，需外接 MPU6050（六轴）—— 但受排针引脚限制，只能走软件 I²C 到 IO21。

## 5. 电源与无线链路的实测问题

第 1 周后期出现**上报断流**（约 18.6% 的时间缺口），排查结论是**环境/硬件问题，非代码**。逐项排除过程见 [`07-排错记录.md`](07-排错记录.md)，这里只列结论：

| 检查项 | 结果 | 结论 |
|---|---|---|
| 板子 RSSI | -32 ~ -38 dBm（极强） | 排除距离/信号弱 |
| ping 网关 10.1.41.254 | 0% 丢包、平均 0 ms | 排除 PC/路由器有线侧 |
| **ping 板子 10.1.41.160** | **33~40% 丢包、平均 ~900 ms** | **问题定位在无线上行最后一跳** |
| 关闭摄像头做对照 | 断流依旧甚至更差 | 排除摄像头抢带宽/CPU |
| 关闭 WiFi 省电（`WIFI_PS_NONE`） | 仍 40% 丢包 | 排除 Modem-sleep |

剩余可能：2.4G 同信道干扰 / AP 拥塞、板子发射功率弱、**USB 供电不足**（强信号 + 高丢包的典型原因）、USB 3.0 口干扰 2.4G。均属环境问题，需物理手段改善。

固件侧的改善（不改架构）：POST 超时 5000→2000 ms（卡住时不拖死主循环 5 秒），新增上报 `rssi` 字段供网页展示信号强度。
