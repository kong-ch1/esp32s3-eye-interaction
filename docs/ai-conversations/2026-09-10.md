## 结论：你这颗是 **QMA6100P**

不是你查错，也不是原理图错——是**文档滞后于物料**。QMA7981 已经 EOL（停产），QMA6100P 是它的 **pin-to-pin 兼容换代型号**（同样 2×2×0.95mm LGA-12 封装、同样 I²C 地址 0x12、同样 14 位 ADC）。乐鑫早期批次的板子焊 QMA7981，后来换料成 QMA6100P，**原理图和用户手册的文案没跟着改，但代码库改了**——这就是你在组件库里只找到 `qma6100p` 的原因。

## 二、摄像头上网页：能，而且是这块板的老本行

三个关键点：

**① OV2640 自带 JPEG 压缩**——它输出的就是 JPEG 码流，ESP32 只负责搬运转发，**不需要芯片自己编码**。这就是为什么这么小的 MCU 也能做图传。

**② 画面不用经过你的服务器。** 板子自己起一个 HTTP 服务（比如 81 端口，MJPEG 流），网页里一行就显示：

```html
<img src="http://10.1.41.160:81/stream">
```

你的 IMU 数据继续走 `127.0.0.1:8000` 那条路，两路并行互不干扰。

**③ 硬前提：必须先开 PSRAM。** 一帧 320×240 的缓冲就是 150KB，按现在"260KB 可用堆"的状态连一帧都放不下——**这就是摄像头会让板子崩的原因**，跟我们上一轮聊的完全是同一件事。

实际性能大概这样（Wi-Fi 2.4G 环境）：

| 分辨率 | 帧率 |
|---|---|
| 160×120 | ~25 fps |
| 320×240 | ~12-15 fps |
| 640×480 | ~5 fps |

**一个坑提前说**：摄像头的 SCCB 配置总线和 IMU 共用 GPIO4/5 那条 I²C，能共存，但两边速率不一样（OV2640 用 100kHz，QMA6100P 支持 400kHz），初始化顺序要注意。

做法上，乐鑫官方有现成的 camera web server 示例（ESP-WHO 里就有这块板的），我要做的话主要工作是：开 PSRAM → 拆任务（摄像头一个任务、IMU 上报一个任务）→ 把流地址引到你的 index.html 里。

**所以顺序建议**：先解决板子启动问题（你插拔一下），拿到型号鉴定结果；摄像头那个等你想清楚了再动手——它是个独立的新功能分支，不影响 week1 已经完成的部分。
