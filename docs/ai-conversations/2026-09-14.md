## 板子怎么把数据传给服务器

其实是**两条方向相反**的通道，别混了：

**① IMU 数据（板子主动「推」给服务器）—— 这就是你说的"传输到服务器"**

| 层 | 用什么 |
|---|---|
| 物理/链路 | ESP32-S3 内置 **WiFi（2.4GHz）** 连到路由器 `431` |
| 网络层 | 板子拿到局域网 IP `10.1.41.160`，服务器在 PC 的 `10.1.41.18` |
| 传输层 | **TCP**（HTTP 跑在 TCP 上） |
| 应用层 | **HTTP POST**，body 是 JSON，`Content-Type: application/json` |

代码里就是这几行（`main.c`）：

```c
#define SERVER_URL  "http://10.1.41.18:8000/api/data"   // PC 的局域网 IP，不是本机
#define POST_INTERVAL_MS  1000                          // 每 1 秒发一条

esp_http_client_init(...);                              // 建连接
esp_http_client_set_post_field(client, json, ...);      // 塞 JSON
esp_http_client_perform(client);                        // 发出 POST
esp_http_client_cleanup(client);                        // 关连接
```

每发一条都是**独立的新连接**（`init`→`perform`→`cleanup` 循环）。JSON 长这样：

```json
{"device_id":"team01-esp32s3eye","seq":560,"ts":...,
 "ax":0.12,"ay":-0.05,"az":1.01,"gx":0,"gy":0,"gz":0}
```

关键点：板子**必须填 PC 的局域网 IP**（`10.1.41.18`），不能填 `127.0.0.1`——那是板子自己。换电脑/换 IP 就要改 `SERVER_URL` 这个宏重烧（顺便提一句，这也是以后做远程访问要改的地方）。

**② 摄像头画面（服务器主动「拉」板子）—— 反向的**

板子自己起了个 HTTP 服务器（**81 端口** `/stream`）。**不是板子推给服务器**，而是 PC 上的 `server.py` 用 `camera_relay.py` 主动去拉这条流，再分发给浏览器。

总结一下：

**两条通道，都跑在「WiFi + TCP + HTTP」上，区别只是方向。**

| 数据 | 方向 | 协议细节 | 频率/格式 |
|---|---|---|---|
| **IMU 加速度** | 板子 **→** 服务器（板子主动推） | HTTP `POST` 到 `10.1.41.18:8000/api/data` | 每秒 1 条，JSON |
| **摄像头画面** | 服务器 **→** 板子（服务器主动拉）再 **→** 浏览器 | 服务器 `GET` 板子 `:81/stream`，再 `multipart` 转发给网页 | 连续 MJPEG |

所以你问的"他是通过什么传输到服务器上面的"——严格说只有 **IMU 那一条是板子主动发往服务器**，走的是 ESP32 的 WiFi 网卡发出的 HTTP POST 请求。摄像头是反过来的：服务器去板子那儿把流"拽"过来再转发。

**为什么这样设计对你"拿出去用"很关键：**
- 板子只认一个服务器地址（`SERVER_URL` 宏），发 IMU 用推、收视频请求靠服务器来拉；

## 结论：现在不行，但加一座"桥"就能行

**为什么现在一出去就断？** 系统里有三处写死在局域网里（`main.c` 和 `camera_relay.py` 实测确认）：

| 写死的东西 | 值 | 出局域网后怎样 |
|---|---|---|
| WiFi 账号密码 | `431` / `88888888` | 外地路由器不一样，板子连不上网 |
| 服务器地址 `SERVER_URL` | `http://10.1.41.18:8000/api/data` | 这是**你家电脑的局域网 IP**，外地网络里根本不存在，POST 直接失败 |
| 摄像头中继 | 服务器去拉 `10.1.41.160:81` | 板子换了网络，服务器再也"拉"不到它 |

所以板子一离开家，IMU 数据发不出去、摄像头也拉不到 —— 网页自然空了。

## 要让"带出去也能用"，需要补三件事

1. **服务器上公网**：把 `server.py` 那台机器通过 **端口映射 / 内网穿透（frp、ngrok 之类）/ 云 VPS** 暴露到互联网，拿到一个公网地址。
2. **板子改指向公网**：把 `SERVER_URL` 从 `10.1.41.18` 改成那个公网地址（最好改成可配置，别每次换都重烧）。板子只要能连上任意 WiFi、能访问这个地址，数据就照传。
3. **摄像头改成板子主动推**：这是最难的一处。现在的设计是"服务器来拉板子的局域网 IP"，远程拉不到。得反过来让板子把 MJPEG 帧主动 POST 给服务器 —— 工作量比 IMU 大，但原理一样。

> 顺带一提：你之前说的"拿出去上传到这个网页"，第 1、2 步就能让 **IMU 数据**远程上传；摄像头要等第 3 步。

5. 你打开网页，网页去问小程序："最新一条是多少？" → 拿到 `1.01` → 画成曲线显示

## 1. 为什么测不了

你板子上的 IMU 是 **QMA6100P**，官方 datasheet 第一句就是 *"The QMA6100P is a three-axis accelerometer"*——**纯三轴加速度计，没有陀螺仪**。立创商城的参数表里"陀螺仪轴向"一栏是**空的**（`-`），传感器类型写"加速度计"。

所以网页上 `gx/gy/gz` 恒为 0 **不是 bug，是硬件没有**。

> ⚠️ 提醒：网上有些页面（etei.com 之类）说 QMA6100P 是"6 轴 IMU 带陀螺仪 ±2000dps"——**那是 AI 生成的错误信息**，连封装都写成 LGA-14（官方是 LGA-12 2×2mm）。别被误导。乐鑫自己的入门指南也写这块板是"三轴加速度传感器"。

## 2. 想用上角速度，三条路

| 方案 | 做法 | 效果 | 成本 |
|---|---|---|---|
| **A. 外挂 6 轴模块** | 买 QMI8658 / MPU6050 / BMI270 带陀螺的模块飞线 | **真角速度**，单位 °/s | 需接线+改代码 |
| **B. 用加速度推算** | 由加速度算倾角 roll/pitch，再对时间求导 | 只能测**慢速倾斜**，一动就被线性加速度污染，噪声大 | 纯软件，零成本 |
| **C. 维持现状** | `gx/gy/gz` 填 0 | 无 | — |

## 3. 硬件上加模块可不可行？（这点很关键）

ESP32-S3-EYE 的 20pin 排针只引出了：
```
3V3  GND  IO48  IO47  IO44  IO21  IO43  IO0  IO3  IO45  IO46
```
其中**真正干净空闲的只有 IO21**，其余都是 strapping 脚或被 UART 控制台 / LCD 占用。而且**板载 QMA6100P 用的 GPIO4/5 那组 I2C 并没有引到排针上**，没法直接并联新芯片。

→ 真要加：买个 GY-521（MPU6050，几块钱），用**软件 I2C** 接 `IO21 + IO3`，从排针取 3V3/GND 供电。可行，但要动烙铁/杜邦线，且 IO3 是 JTAG strapping 脚，接线要谨慎。

## 4. 一个好消息：软件链路早就预留好了

`gx/gy/gz` 这三个字段——**固件的 JSON、服务器的数据库表、网页的显示位置全都已经存在**，只是现在填 0。将来只要读到真陀螺数据填进去，网页立刻就有角速度曲线，**服务端和网页一行都不用改**。

## 5. 从课程角度说

单元1 的评分要求是"**1 个真实传感源**"——加速度计已经满足了。**加陀螺是加分项，不是必需项**。如果目标是"让数据源更丰富"，其实用你已有的摄像头，或者第 3 周本来就要做的板载按键，投入产出比更高。

## 这三个数，其实是「同一件事的三个分量」

拿你板子**此刻的真实读数**来说（16:54:30，刚从服务器读的）：

```
ax =  0.0366 g
ay = -0.0085 g
az = -0.9982 g
合起来 |a| = √(ax²+ay²+az²) = 1.00 g
```

想象你手里有一根**箭头**，代表"芯片此刻被推动的方向和力度"。这根箭头在三维空间里指着某个方向，我们把它拆成三个互相垂直的方向去量——**前后（X）、左右（Y）、上下（Z）**，每个方向量到的那截，就是 ax / ay / az。

所以它们**不是三个独立的传感器，是同一个物理量的三种投影**。这也是为什么板子不动时三个数加起来（勾股）恒等于 1：箭头长度没变，只是方向在变。

**单位 g 是什么**：1 g = 9.8 m/s²，就是地球表面一个物体的重力加速度。所以 `ax = 0.037 g` 换算成物理单位就是 0.037 × 9.8 ≈ **0.36 m/s²**。用 g 做单位的好处是直观：看到 1 就知道"相当于一个重力"。

## 为什么叫"加速度"，却能量出重力？

这是最容易困惑的一点。芯片内部其实是**一根弹簧吊着一个小质量块**（见上图右边）：

- **板子平放不动** → 重力把质量块往下拽，弹簧被压住 → 输出 **1.0 g**
- **板子自由落体** → 质量块和外壳一起掉，弹簧不受力、松开 → 输出 **0 g**

所以它真正测的不是"你在不在动"，而是**"外壳有没有在推这个质量块"**（工程上叫比力 / proper acceleration）。只是这个力的大小用加速度单位标定，所以叫加速度计。

**两个反直觉但重要的推论：**

1. **静止 ≠ 读数为 0**，静止 = 读数 1 g（因为你一直被地球拉着）。
2. **真正自由下落时反而是 0**，尽管它正以 9.8 m/s² 加速。

你手机能自动转屏，靠的就是同样的东西——它读出重力落在哪根轴上，就知道你把手机横过来了。

## 负号是什么意思？你板子现在什么姿态

负号只表示**方向和轴的正向相反**，不代表故障。你现在 `az = -0.998`：重力几乎全部落在 Z 轴上（反方向），说明**板子基本是平放的**，Z 轴竖直朝上或朝下。

如果把它竖起来（像手机立着），会看到 Z 变成接近 0，而 Y 或 X 变成接近 ±1——**|a| 仍然还是 1**。这就是"倾斜不会改变合值，只改变分配"。

## 三种"数字在变"要分清楚

| 现象 | 原因 | 正常吗 |
|---|---|---|
| 数值跳 ±0.01~0.06 g | 芯片噪声 + 环境微振动（上次实测过） | 正常 |
| 三个数大幅变化，但 **\|a\| 仍是 1** | 板子被转动/倾斜了 | 正常，姿态变了 |
| **\|a\| 明显偏离 1**（比如 1.5 或 0.3） | 真在动：手晃、桌子被敲、掉落 | 看场景 |

所以判断板子有没有真被移动，**别看单个轴，看 |a|**（就是网页上那个「合加速度」卡片，我特意加的）。这也正好解释了上次那件事：你以为板子没动，`ax` 却从 0.009 跳到 0.047——那是第一种噪声；而 |a| 稳稳停在 1.00，说明姿态其实没变。

想亲手验证的话：把板子**慢慢倾斜**过来看网页——你会看到 az 从 -1 一路变小、另一个轴一路变大，而 |a| 始终贴着 1.00 不动。
