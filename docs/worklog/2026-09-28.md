# 2026-09-28 工作日志

## 网页视觉改版（用户要求「优化网页」）

先量化再动手。用真实 Chrome 在 1280px 下量各区块高度，发现两处明显不合理：
**解释性文字占掉的面板比数据还大**（教学求助 26.4%、摄像头 19.7%），
而**核心实时数据只占 8%**。整页 2743px。

用户选了三个方向（多选）：布局与信息层级、趋势图改进、深色模式与视觉精修；
幅度选「保持现有风格精修」。**没有选移动端适配**（但也不能弄坏）。

### 做了什么

1. **设计令牌化** —— 原来散着二十多个写死的色值（同一个"浅灰底"在 6 处各写一遍），
   这种写法没法加深色模式。收成 `--surface-2` / `--ok-fg` / `--s-ax` 等语义变量，
   深色只需重定义一组值。`color-scheme: light dark` 让原生控件跟着走。
   画布颜色走 `getComputedStyle` + `matchMedia` 监听（canvas 不认 CSS 变量）。
   批量替换用脚本并**断言每条命中次数**，真的拦住了两次写错模式的替换。

2. **信息层级** —— 两处长说明折成 `<details>`（summary 留结论、只折推导过程）。
   顺手修一个真问题：`#cmdHint` 既当静态说明又当实时状态，JS 一下发指令就把说明
   覆盖掉了 → 那段说明只能看一次。7 张卡片按"回答什么问题"分成两组。

3. **趋势图** —— 时间窗（1/10/60 分钟）、横轴按真实时间定位 + 空档断线、
   纵轴最小跨度 0.25g、悬停读数（独立画布层）。

4. 其他：摄像头限高 340px、求助列表默认 3 条、表格横向溢出收进容器、
   补 `:focus-visible`、修 `colspan="9"`（表格是 10 列）。

### 踩到并修掉的坑

1. **`/api/history` 是"取最近 N 条"不是"按时间"** —— 加时间窗时直接用了 limit，
   实测 `limit=3600` 返回的 3600 条**跨了 4.6 天**（设备有离线空档）。
   那样界面写着"最近 1 小时"、画的却是 4 天。→ 给接口加 `minutes` 参数，
   时间范围由服务器按时间过滤，limit 只当安全上限（上限同时 500 → 4200）。

2. **纵轴自动缩放把噪声放大成"故障"** —— 板子静止时噪声只有约 ±15mg，
   原来的自动缩放会把它撑满整个图高，看着像剧烈抖动。加了 0.25g 最小跨度。
   **刻意没用分位数裁极值**：本页面盯的正是加速度峰值，裁掉尖峰等于藏证据。

3. **横轴按下标均分会伪造数据** —— 设备离线那段会被压成一条水平直线，
   看起来像"这段时间一直是这个值"，而事实是这段时间根本没有数据。
   改成按真实时间定位 + 空档处断开曲线。

4. **审计里的"没有 JS 报错"是个假通过** —— 它读的是一个**从没被写入过的列表**，
   所以必然通过。**一个永远为真的检查等于没有检查。** 改成加载前注入错误监听，
   并**先故意抛一个错验证探测器本身有效**再清空重测（照搬第 2 周失败态验证的对照思路）。

5. **目视判断图像不可靠** —— CDP 模拟深色后 JS 回读背景色明确是 `rgb(25,25,23)`，
   但我看截图觉得还是浅色，白花时间去找 CSS 的问题。写了 `tools/img_sample.py`
   （标准库解 PNG）采样：平均亮度 36.8 vs 243.3 —— **深色一直是生效的**。
   以后"看着像"的结论都先用它验一遍。

6. **测量口径不一致会污染文档** —— 中途把一次"PNG 高度 ÷ 2"当页高写进文档，
   和另一次测量的口径不同。改用**同条件复测**：把 git 里的旧文件临时放回原位
   （同源、无 CORS），同一脚本量三档视口，测完还原并核对 md5。
