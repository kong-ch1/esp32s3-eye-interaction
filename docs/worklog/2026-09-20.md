## 安全网目录清理（用户问「不是只有4个吗 / 我删了4个，还有1个在哪里」）

### 事实核对
- 9/18 重建历史时共留下 **5 个**安全网条目；用户在 9/20 手动删除了其中 **4 个**
  （`aijiaohu_backup_20260918_094332`、`aijiaohu_backup_20260918_094342`、
  `aijiaohu_hold`、`aijiaohu_repo_build`），已确认磁盘上不存在。
- **剩下的是 `D:\aijiaohu_git_attempt1`**，它带 **`FILE_ATTRIBUTE_HIDDEN`（隐藏）属性**
  —— 这是从 `.git` 改名来的，Windows 上 `.git` 目录默认隐藏，改名后属性被继承，
  所以资源管理器里默认看不见。**用户看到的"4个"就是不含这个隐藏目录**。
  → 排查方法：`os.stat(p).st_file_attributes & stat.FILE_ATTRIBUTE_HIDDEN`。

### 该目录内容（实测）
- 363 个文件 / 5.6 MB；是**非裸仓库**结构（含 `HEAD`/`config`/`objects`/`refs/heads/main`）。
- **19 个提交**，2026-09-08 → 09-18，作者 `team01 <team01@example.com>`
  —— 即**第一版历史**（时间戳只到秒、9 个提交被压平、身份尚未改写）。
- 用 `git --git-dir="D:/aijiaohu_git_attempt1" rev-list --count HEAD` 读取有效；
  注意 Git Bash 里必须用 **`D:/...` 正斜杠 Windows 路径**，用 `/d/...` 会失败。

### 安全性结论
- 当前主仓库：**45 个提交、267 个受控文件、分支 `main` + `week2-downlink`**，
  **本地 HEAD `0f58b5c` = 远端 main `0f58b5c`**（已完全同步）。
- 故 `aijiaohu_git_attempt1` 已是**纯冗余**，可安全删除。
- ⚠️ 唯一禁忌：**不要删 `D:\aijiaohu`**（那是项目本体）。

### 工具经验（复用价值高）
- `os.scandir` / `os.listdir` **会列出隐藏文件**，排查"看起来少了"的目录时可信；
  资源管理器不会 → 两者结果不一致时优先信 Python。
- 查"东西是不是被删了"不能只看目标路径，要**解析回收站**：
  `D:\$RECYCLE.BIN\<SID>\$I*` 是元数据（8B 版本 + 8B 大小 + 8B FILETIME + 4B 名长 + UTF-16 原名），
  `$R*` 是实际内容。本次解析确认回收站里**没有任何 aijiaohu 条目**
  → 用户删的 4 个是"永久删除"（绕过回收站）或已清空。
- 沙箱内 `Add-Type` 被拦，**无法用回收站 API**；本机 Python 的 `os.remove` 是硬删除，
  不会进回收站 —— 所以删除类操作交给用户自己在资源管理器做更安全。

## 第3周完成：实体按键 + 本地 LED / 远端网页反馈闭环

### 硬件侦察（动手前先查，不猜）
- **按键**：原理图第 4 页 `4-Keys: ADC1_CH0` → 四个键共用 **GPIO1** 的电阻梯。
  实测 UP+ 365~367 / DN- 800~802 / PLAY 1981 / MENU 2409~2414 mV，空闲 3162 mV，
  与原理图标注值（380/820/1980/2410）偏差 ≤20 mV。**判读用相邻两档中点做边界。**
- **本地反馈只能用 LED**：本板**没有蜂鸣器**、**没有 RGB 灯**；唯一软件可控的是
  绿色 Module Power LED = **GPIO3**，官方要求**开漏驱动、不得上拉，否则可能烧 LED**。
- 原理图 PDF 文本提取要用 `pypdf` 的 **`extraction_mode='layout'`**：
  普通模式把按键名与电压提取成乱序，靠列坐标配对才正确。
- 核验工具 `tools/btn_probe.py`；上电自检闪 3 次，用户确认"闪了 3 次"。

### 固件三取舍
① 灯效走队列 + 独立 `led_task`（在按键任务里 `vTaskDelay` 闪灯会丢按键）
② 按键采集放主循环（HTTP 全工程只有主循环一个使用者，两个任务会争 seq/http_client）
③ 消抖 3 次 + 只在「抬起→按下」边沿触发（长按不重复）
