## 板载 IMU 型号判定：原理图写 QMA7981，实装是 QMA6100P
- 用户提问：原理图/手册标 QMA7981，但乐鑫组件库只有 qma6100p，到底是哪个？
- **结论：实装为 QMA6100P**。QMA7981 已 EOL 停产，QMA6100P 是其 pin-to-pin 兼容换代型号（XPU Labs / AnalogLamb 两家 breakout 说明均明确写了这句）
- 证据链：
  1. 本板实测 chip_id(0x00)=0x90 = QMA6100P 的 WHO_AM_I（esp-bsp 定义 `QMA6100P_WHO_AM_I_VAL 0x90u`）；QMA7981 公开手册为 0xE7
  2. ±2g 量程码 0b0001（我们实测 0x00 非法）与 qma6100p_acce_fs_t 枚举完全一致
  3. 数据格式 14 位补码、LSB[7:2]=data[5:0]、LSB[0]=NEWDATA —— QMA6100P 手册定义
  4. 软复位 0x36（写 0xB6）有效 = QMA6100P_REG_SW_RESET，QMA7981 手册无此寄存器
  5. esp-bsp 的 commit "add qma6100p accelerometer" 就加在 `bsp/esp32_s3_eye/idf_component.yml` 下
- **重要回顾：week1 调试时踩的所有坑（量程值不对、数据格式对不上、Y 轴上电冻结）根源都是"按 QMA7981 手册写、实际芯片是 QMA6100P"**
- 现有 main.c 驱动实际已按 QMA6100P 真实行为编写（0x0F↤0x01、0x36 软复位、0x11↤0xC0 先退出睡眠），无需改动
- 待办（可选）：可用官方 qma6100p 组件替代自写驱动；判定实验可加读 0x45 CHIP_STATE / 0x46 ULPS / 0x5F TST1_ANA（QMA6100P 特有）

## ✅ 用户插拔 USB 后恢复，鉴定实验跑通（结论更新）
- 用户拔插 USB 后板子恢复正常，`boot:0x2a (SPI_FAST_FLASH_BOOT)`，串口出日志
- **软件复位可用序列（经验证）**：`dtr=False, rts=False` → `rts=True` → sleep 0.2 → `rts=False`（即 RTS=EN 低脉冲）。之前失败是板子本身卡 download，不是序列错
- **实测鉴定输出（决定性证据）**：
  - `CHIP_ID(0x00) = 0x90` → QMA6100P
  - QMA6100P 特有寄存器全部 ACK：0x33 NVM=0x0d / 0x45 CHIP_STATE=0xc0 / 0x46 ULPS=0x1a / 0x4a TST0_ANA=0x00 / 0x56 AFE_ANA=0x00 / 0x5f TST1_ANA=0x00
  - 量程接受性：0x01(±2g)/0x02(±4g)/0x04(±8g)/0x08(±16g)/0x0f(±32g) 全部写入即读回 = QMA6100P 位编码方案，0x00 非法（解释了早期模长 1.5g 异常）
  - 结束后恢复 0x01，数据继续正常：|a|≈1.00，HTTP 200
- **结论确认为 QMA6100P，无争议**
