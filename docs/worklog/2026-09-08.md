## num_ctx 实测（本机 32GB 内存 + RTX 5070 12GB）
- 四档全跑通，4096 只是 ollama 默认值，模型上限 262144：
  | num_ctx | 首响 | total | size_vram |
  | 4096 | 1.4s | 18.20G | 8.55G |
  | 16384 | 17.5s | 18.70G | 8.36G |
  | 65536 | 22.0s | 21.32G | 6.90G |
  | 262144 | 52.0s | 34.61G | 5.06G |
- **反直觉结论**：上下文开大会反向挤走显存里的权重（8.55G→5.06G），更多层被赶到 CPU，推理更慢；256K 时 total 34.61G 超 32G 物理内存，会走页面文件。
- 建议值：日常 8192，长文档 16384~32768，别开 256K。
- `ollama run` **无** --num_ctx 参数（已验证），只能对话内 `/set parameter num_ctx N`、API `options.num_ctx`、或 Modelfile `PARAMETER num_ctx N`。

## num_ctx=32768 实测（补充上一轮）
- 32K 加载成功：ollama ps 显示 CONTEXT=32768，PROCESSOR 60%/40% CPU/GPU。
- 实测：total(size)=19.54GB，size_vram=**7.73GB**，load_duration=17.4s，eval_rate=**9.2 tokens/s**（69 token / 7.5s）。
- 完整趋势（size_vram 随上下文反向下降）：
  4096→8.55G / 16384→8.36G / **32768→7.73G** / 65536→6.90G / 262144→5.06G。
- 结论：32K 可用、代价温和（比默认 4096 多 ~1.3GB 内存、显存少 0.8GB、速度约降 10-15%），日常长文推荐档位。
